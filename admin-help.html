A complete reference for managing customers, orders, picking, deliveries, and the product catalogue — all from the admin portal.

▦
How the Admin App Works

The admin portal is the operational hub for the entire platform. You control everything here — the product catalogue, customer approvals, order lifecycle, picking and delivery. Customers cannot manage themselves; all approvals, status changes, and notifications flow through you.

👤
Customers
Approve new registrations, send OTP codes via WhatsApp, view delivery locations, and suspend accounts if needed.
📋
Orders
View all orders, move them through the lifecycle, and send automatic WhatsApp status notifications to customers at each stage.
🛒
Picking
Generate per-order picking cards grouped by store. Share picking lists with pickers via WhatsApp. Capture till slips per order.
🚚
Delivery
Generate an optimised delivery route for each window. Share the run with the driver via WhatsApp. Mark orders delivered on the road.
🏪
Catalogue
Add and manage stores, categories, and products. Upload product images via drag and drop. All changes are live immediately.
⚙
Settings
Configure delivery pricing (fuel, multiplier, minimum fee), base location, delivery windows, cutoff times, and app name.
🔑
Signing In

The admin app is protected by a PIN set in Google Apps Script Script Properties — not stored in the spreadsheet. This means it is never visible to anyone with sheet access.

1
Open admin.html in your browser
The login screen appears immediately. No username is required — only the PIN.
2
Enter your Admin PIN and press Enter or tap Sign In
The PIN is verified securely against Apps Script Script Properties. It is never sent back to the browser.
3
Your session is saved for 24 hours
Closing and reopening the browser tab will keep you signed in until the session expires or you sign out manually.
⚠ If you see Unauthorised errors after updating the backend: delete all rows below the header in the SESSIONS sheet, then sign in fresh. Sessions use a numeric timestamp — old string-format sessions from earlier versions will not validate.
🔑 To change your Admin PIN, go to the Apps Script editor → Project Settings → Script Properties → edit the AdminPIN value. No redeployment needed for a PIN change.

Dashboard

The dashboard loads automatically when you sign in. It gives you a live count of activity across the platform and shows the 10 most recent orders.

🟡
Pending Orders
Orders placed by customers that have not yet been confirmed. This number also appears as a badge on the Orders nav item.
🔵
Active Orders
Orders currently in progress — confirmed, picking, packed, or delivering.
🟢
Delivered Today
Orders marked as delivered. Useful for end-of-day reconciliation.
👤
Pending Customers
New registrations waiting for approval. A badge also appears on the Customers nav item when this is non-zero.
↻ Tap the Refresh button on the dashboard to reload live counts without navigating away.

Managing Customers

Every new customer starts with a pending status. They cannot browse or order until you approve them and they complete phone verification.

1
Customer registers on the public app
Their account appears in the Customers list with status pending.
2
You tap Approve in the Customers panel
The system generates a 6-digit OTP valid for 30 minutes and prepares a WhatsApp message.
Auto
3
WhatsApp opens with the OTP pre-filled
You tap Send in WhatsApp. The message goes to the customer's number with their verification code.
WhatsApp
4
Customer enters the code in the app
Their account becomes active and they can immediately start shopping.
Customer
📍View Customer Location
Tap the map pin icon on any customer row to open a read-only map showing their pinned delivery address. Useful for planning delivery routes and verifying that the address is correct.
⏸Suspending a Customer
Tap the suspend button on a customer row. A confirmation prompt will appear. Suspended customers cannot log in. You can filter by status to find suspended accounts and reactivate them by contacting you directly.
🔎 Use the status filter at the top of the Customers panel to show only Pending accounts — makes approvals faster during busy registration periods.

Managing Orders

Orders move through a fixed lifecycle. Every status change sends an automatic WhatsApp notification to the customer — the WhatsApp link opens ready to send with a single tap.

StatusWhen to set itCustomer notification
Pending Set automatically when the customer places an order. No action needed. Order confirmation sent by the customer app automatically.
Confirmed Once you have reviewed the order and are happy to proceed. Customer is told their order is confirmed and will be picked soon.
Picking When the picker leaves to shop for this order. Customer is told their items are being shopped.
Packed Set automatically when a till slip is attached. Can also be set manually. Customer receives till slip and order summary via WhatsApp.
Delivering When the driver sets off for deliveries. Customer is told their order is on the way and reminded of the amount due.
Delivered After the driver confirms delivery at the door. Customer receives a delivered confirmation message.
Issue If something goes wrong — missing item, address not found, payment refused. Customer is told there is an issue and that they will be contacted.
Cancelled If the order cannot proceed for any reason. Customer is notified of the cancellation.
1
Find the order using the filters
Filter by status and/or delivery window to narrow the list. Use the status filter to show only Pending orders that need confirmation.
2
Tap the edit icon to update the status
Select the new status from the dropdown. Optionally add a note — this appears in the customer's WhatsApp notification.
3
Tap Update & Notify
The status is saved and WhatsApp opens automatically with the notification pre-filled. Tap Send in WhatsApp to deliver it to the customer.
🧾 If a till slip has been attached to an order, a till slip icon appears in the order row. Tap it to view the image in a new tab.
🛒
Picking Lists

Picking lists show you every order that needs to be shopped for a given delivery window. Orders are grouped by store, then broken into individual per-order cards — one card per customer per store. Each order is picked and paid for separately.

1
Select a delivery window
Use the dropdown at the top of the Picking Lists panel and tap Load. Only orders that are Confirmed or beyond (not Pending or Cancelled) appear.
2
Review the store sections
Each store appears as a separate card. Inside each store you see individual order picking cards — one per customer. The card shows the customer name, payment method, total due, and item list with quantities and substitution rules.
3
Share the picking list with your picker
Tap Share List on a store section. Enter the picker's phone number. WhatsApp opens with the full picking list for that store pre-filled. The picker sees each order as a numbered section with all items listed.
4
Picker shops each order separately
Each customer's items are picked and paid for as a separate transaction. One till slip per order per store.
📱 Pickers can receive the list on any phone — they do not need the admin app. The WhatsApp message is fully formatted with store name, window time, and numbered order sections.
🧾
Till Slip Capture

After each order is picked and paid, photograph the till slip and attach it to the order. This gives the customer a receipt before their delivery arrives and creates an audit trail for every order.

1
Open the picking card for the order
Find the order in the Picking Lists panel under its store section.
2
Tap Capture Till Slip
On mobile this opens your camera directly. On desktop, a file browser opens. Take a clear photo of the till slip or select an existing image.
3
Image uploads to ImgBB automatically
The image is uploaded in the background. A confirmation toast appears when it is saved. The order status moves to Packed automatically.
Auto
4
Tap Send via WhatsApp
WhatsApp opens with the order summary and a link to the till slip image pre-filled. Tap Send to deliver it to the customer. The customer also sees the till slip link in their order history.
WhatsApp
💡 Send via WhatsApp only appears after the till slip has been uploaded. This ensures customers always receive their receipt before delivery confirmation.
⚠ ImgBB images are public. Anyone with the URL can view the image. Till slips should not contain sensitive personal information beyond the order total and items.

Delivery Run

The Delivery Run panel builds an optimised route for a delivery window. Only orders in Packed or Delivering status appear here. The route visits stores first (furthest from base first), then delivers to customers.

1
Select the delivery window and tap Load
The system calculates the circuit route — base depot to stores (furthest first) then to each customer, and back to the depot.
2
Review the route
Store stops are numbered 1, 2, 3… in gold. Customer stops are lettered A, B, C… in blue. Each customer stop shows the address, total due, and payment method. Tap the phone icon to call a customer directly.
3
View on Map
Tap View Map to open the full route visualised on an OpenStreetMap with numbered markers and a connecting route line.
4
Share Run with driver
Tap Share Run and enter the driver's phone number. WhatsApp opens with the full ordered stop list — store addresses first, then customer stops with amounts due and payment methods.
5
Mark deliveries as Delivered
As each delivery is completed, tap the Delivered button on the customer stop. A confirmation prompt appears, then WhatsApp opens with the customer's delivery confirmation message ready to send.
📏 The total km for the run is shown at the top of the route view. This matches the distance used to calculate each customer's delivery fee.
🏪
Stores

Stores are the shops your pickers visit. Each store has a GPS location used for route planning and delivery fee calculation. You must add at least one store before adding products.

+
Adding a store
Tap Add Store. Enter the store name, category (e.g. Grocery, Pharmacy), and street address. Then tap the map button to pin the store's exact location — drag the pin to the store entrance for the most accurate routing.
✎
Editing a store
Tap the edit icon on any store row. All fields including the map location can be updated. Changes take effect immediately for future orders — existing orders are not affected.
✕
Deactivating a store
Tap the deactivate icon. The store is hidden from customers but not deleted. Its products and order history are preserved. Reactivation requires directly updating the STORES sheet active column to true.
📍 The store's GPS coordinates directly affect delivery fee calculation and route optimisation. Always pin the store as accurately as possible.
📦
Products

Products belong to a store and optionally a category. Customers browse products per store in the customer app. Product availability is not tracked — the picker handles stock issues using substitution rules.

➕
Adding a Product
Tap Add Product. Select the store, category, and fill in the name, size, and price. Barcode is optional but useful for picker scanning in future. Description is shown to customers in the product detail view.
📷
Product Images
Drag and drop an image onto the upload zone or tap it to browse files. Images upload to ImgBB automatically. On mobile you can use the camera. Paste a URL directly into the hidden field if preferred.
📱
Barcode Field
Enter the product barcode number if known. This appears on picking cards so pickers can scan items to confirm picks. Full scanner integration is planned for a future update.
💰
Pricing
Prices are the amounts charged to the customer — set these to the typical shelf price at the store. Actual till slip prices may vary slightly due to promotions or price changes.
💡 Use the store filter at the top of the Products panel to view and manage products for one store at a time. This keeps the list manageable when you have many products across multiple stores.
📂
Categories

Categories are two levels deep — a parent category (e.g. Dairy) and optional child categories (e.g. Milk, Cheese, Yoghurt). Customers use category pills to filter products while browsing.

1
Add parent categories first
Tap Add Category, enter the name, and leave the parent field blank. Examples: Dairy, Bakery, Meat, Frozen, Household, Personal Care.
2
Add child categories
Tap Add Category again, enter the child name (e.g. Milk), and select the parent from the dropdown. Child categories appear indented inside their parent when browsing.
3
Assign products to categories
When adding or editing a product, select the most specific category that applies. A product in a child category will also appear when the parent category pill is selected.
🗓
Delivery Windows

Delivery windows are recurring weekly time slots. Customers choose a window when checking out. Each window has a maximum order capacity — once full, customers cannot select it.

➕
Adding a Window
Tap Add Window. Select the day, set the start and end times, and set the maximum number of orders allowed in this slot. The window is active immediately.
⏸
Enabling / Disabling
Each window card has an Enable/Disable button. Disabled windows do not appear to customers. Use this for public holidays or when you know you cannot operate a slot.
✎
Editing
Tap Edit on any window card to change the day, time, or capacity. Changes apply to new orders only — existing orders for this window are not affected.
📊
Capacity Planning
Set the max orders to a number you can realistically fulfil in one run. Factor in picker time per order and your delivery area size. Start conservative and increase as the operation scales.

Settings Reference

All settings are stored in the SETTINGS sheet and editable from the admin portal. Changes take effect immediately for new calculations — no redeployment needed. Tap Save next to any field after editing.

app_nameThe name shown in the customer app topbar and in all WhatsApp messages. Change this to your business name.
base_latitudeGPS latitude of your depot or starting point. Used as the start and end of every delivery circuit. Set this via the map button in Settings.
base_longitudeGPS longitude of your depot. Set together with base_latitude using the map button.
fuel_priceCurrent fuel price per litre in Rands (e.g. 22.00). Update this whenever fuel prices change to keep delivery fees accurate.
vehicle_km_per_litreYour delivery vehicle's fuel consumption in km per litre. Check your vehicle's spec sheet or track it manually over a few tanks.
delivery_factorA multiplier applied to the raw fuel cost to cover time, wear, and operational overhead. Default is 1.8. Increase for premium service or higher-cost areas.
minimum_delivery_feeThe floor delivery fee in Rands (e.g. 35). No delivery will cost less than this regardless of distance. Final fee is always rounded up to the nearest R5.
daily_cutoff_timeThe time (HH:MM) after which no new orders are accepted for the same day. Example: 08:00 means orders placed after 8am are scheduled for the next available window.
whatsapp_numberYour business WhatsApp number with country code, digits only — no spaces or dashes. Example: 27831234567. Used for customer enquiry links.
delivery_window_minutesThe duration of each delivery window in minutes. Informational only — used in future scheduling features.
⛽ Update fuel_price regularly — even small fuel price changes affect every customer's delivery fee. The formula is: (km ÷ kpl × fuel_price) × factor, rounded up to nearest R5, minimum fee applied.

Deployment Notes

These are the critical things to know when setting up or updating the platform for the first time.

⚠Always deploy a new version after changing Code.gs
Saving the file in the Apps Script editor does NOT update the live URL. After every change you must go to Deploy → Manage Deployments → New Version. The URL stays the same but the code updates.
🔧Run setupSheets() once on a new installation
Open the Apps Script editor, select the setupSheets function from the dropdown, and tap Run. This creates all 14 sheets with the correct headers and seeds default settings. It is safe to run again — it will not overwrite existing data.
🔑Set AdminPIN in Script Properties
In the Apps Script editor go to Project Settings → Script Properties → Add property. Set the key to AdminPIN and the value to your chosen PIN. This is never visible in the spreadsheet.
📋Clear the SESSIONS sheet when changing session logic
If you update Code.gs and change session handling, delete all rows below the header row in the SESSIONS sheet. Old sessions will fail to validate against the new logic — a clean sheet forces fresh logins.
🔗Paste your Web App URL into both HTML files
After deploying, copy the Web App URL from Apps Script. Open index.html and admin.html and paste it as the value of const API = '...' near the top of the script block in each file.
📷Add your ImgBB API key to admin.html
Register free at imgbb.com and get an API key. Paste it as const IMGBB_KEY = '...' in admin.html. This is required for product image uploads and till slip capture.
// Deployment checklist — top of admin.html and index.html
const API = 'https://script.google.com/macros/s/YOUR_ID/exec';
const IMGBB_KEY = 'your_imgbb_api_key'; // admin.html only
